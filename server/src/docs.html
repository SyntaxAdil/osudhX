OSUDHX API Reference

REST API for the OSUDHX Smart Pharmacy Management System — categories, products, orders, and wishlist, secured with a better-auth issued JWT and role-based authorization across two roles: customer and seller.

Base URL (prod) — [Live Backend URL]
Base URL (local) — http://localhost:5000/api
Auth — JWT Bearer (issued by better-auth)
Format — application/json

Conventions

All bodies are JSON. Timestamps are ISO 8601 UTC. IDs are UUID strings. Monetary fields (price, totalAmount) are integers. Soft-deleted records (isDeleted = true) never appear in list/detail responses — this applies to categories, products, and orders. Wishlist entries have no soft-delete flag; removing one is a hard delete.

Paginated list endpoints accept page and limit query params and return a meta object alongside data: { page, limit, total, totalPages }.

🔒 marks endpoints requiring a JWT. A role label (e.g. Seller) marks additional role restriction. Some endpoints also enforce resource ownership (e.g. a seller can only edit their own products) — noted per endpoint.

Authentication

Auth is fully handled by better-auth — there are no custom /api/auth/register or /api/auth/login endpoints in this API. Sign up and sign in against better-auth's own routes (mounted separately, typically under /api/auth/*), which issue a session and a JWT.

Send the JWT on every protected request:

Authorization: Bearer <token>

The token is verified server-side against better-auth's JWKS endpoint. Invalid/expired tokens → 401. Valid token, wrong role → 403.

POST better-auth sign-up endpoint Public

Request body (shape depends on better-auth config)
{
  "name": "Ayesha Rahman",
  "email": "ayesha@example.com",
  "password": "StrongPassword123",
  "role": "customer"
}

role is either customer or seller.

POST better-auth sign-in endpoint Public

Request body
{ "email": "ayesha@example.com", "password": "StrongPassword123" }

Response includes the session/JWT used as the Bearer token above.

Response Format

Success
{
  "success": true,
  "message": "Product retrieved successfully",
  "data": {},
  "meta": {}
}

meta only appears on paginated list endpoints.

Error
{
  "success": false,
  "message": "Product not found"
}

Error Handling

Every controller is wrapped in a shared asyncHandler. Services throw a typed ApiError(statusCode, message) for expected failures (not found, forbidden, conflict, bad request); anything unexpected falls back to 500. Either way the response shape above stays consistent.

Products

POST /api/products 🔒 Seller

{
  "name": "Paracetamol 500mg",
  "description": "Pain and fever relief tablets",
  "price": 25,
  "stock": 500,
  "image": "https://...",
  "manufacturer": "Square Pharmaceuticals",
  "categoryId": "cat_01h..."
}

status is set automatically — available if stock > 0, otherwise stockout. Errors: 401 · 403 · 404 category not found

GET /api/products Public

Query params: search, categoryId, status, page, limit, sortBy, sortOrder

GET /api/products/:id Public

PATCH /api/products/:id 🔒 Seller (owner)

DELETE /api/products/:id 🔒 Seller (owner)

Restricted to the seller who created the product — 403 if another seller tries to edit or delete it. Delete is a soft delete.

Orders

POST /api/orders 🔒 Customer

Request body
{
  "shippingAddress": "House 12, Road 4, Dhanmondi, Dhaka",
  "phone": "+8801XXXXXXXXX",
  "items": [
    { "productId": "prd_01h...", "quantity": 2 },
    { "productId": "prd_02h...", "quantity": 1 }
  ]
}
201 Created
{
  "success": true,
  "message": "Order placed successfully",
  "data": {
    "id": "ord_01h...",
    "status": "pending",
    "totalAmount": 75,
    "orderItems": [
      { "productId": "prd_01h...", "quantity": 2, "price": 25 },
      { "productId": "prd_02h...", "quantity": 1, "price": 25 }
    ]
  }
}
Stock-aware ordering: the whole order runs inside a single Prisma transaction. Every item's availability and stock is checked before anything is committed, and each item's price is snapshotted onto OrderItem.price — totalAmount is always computed server-side, never trusted from the client.
Order Created ↓ Check Each Item: exists, available, enough stock? │ ├── No ──▶ 400 Bad Request / 404 Not Found │ Yes ↓ Create Order + OrderItems → Decrement Stock ↓ Stock hits 0? ──▶ Product status → stockout

GET /api/orders 🔒 Customer / Seller

Customers see only their own orders. Sellers see orders that contain at least one of their own products. Query params: page, limit, status, sortOrder

GET /api/orders/:id 🔒 Owner / Seller-in-order

PATCH /api/orders/:id/status 🔒 Seller

{ "status": "confirmed" }

Restricted to a seller with a product in the order. Cannot change status once an order is cancelled or delivered.

PATCH /api/orders/:id/cancel 🔒 Customer (owner)

Only the customer who placed the order, and only while it's still pending. Stock is restored for every item.

Wishlist

POST /api/wishlist 🔒 Customer

{ "productId": "prd_01h..." }

Errors: 404 product not found · 409 already in wishlist

GET /api/wishlist 🔒 Customer

Query params: page, limit, sortOrder

GET /api/wishlist/:id 🔒 Customer (owner)

DELETE /api/wishlist/:id 🔒 Customer (owner)

Hard delete — a wishlist entry is a simple save/unsave toggle with no other mutable state.
